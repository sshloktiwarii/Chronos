# Chronos Orchestrator

> **Stateful DAG Orchestration, In-Memory COW Virtual Filesystem & Failure Recovery for Autonomous AI Agents**

Chronos solves the **Non-Determinism Problem** in multi-step AI reasoning loops. Because large language models are probabilistic and stateless, a 20-step execution task compounding error rate leaves only a small probability of end-to-end success ($0.85^{20} \approx 3.8\%$). When step 12 encounters a compiler error or hallucinates, standard agent loops crash or enter expensive infinite retries.

Chronos converts sequential agent interactions into a deterministic, transactional Directed Acyclic Graph (DAG) state machine with sub-millisecond rollback recovery.

---

## Core Architecture

- **In-Memory Copy-on-Write (COW) Virtual Filesystem (`chronos.vfs`)**:
  - Intercepts file operations in an in-memory COW layer indexed by step sequence.
  - Rolling back a failed step is an $O(1)$ memory pointer swap without physical disk writes, eliminating SSD wear and I/O bottlenecks.
  - Supports spawning multiple speculative branches in parallel ($B_1, B_2, B_3$), allowing an agent to test candidate solutions concurrently and commit only the winning branch to disk.
- **Directed Acyclic Graph (DAG) Engine**:
  - Resolves node dependencies and determines deterministic topological execution order.
  - Supports conditional execution gates, failure fallback nodes, and configurable retry budgets.
  - Integrates a dynamic hardware backpressure governor, adjusting DAG concurrency in response to upstream inference pressure signals.
- **Transactional State Persistence**:
  - Maintains an immutable checkpoint ledger using SQLite Write-Ahead Logging (`PRAGMA journal_mode=WAL;`).
  - Records execution snapshots, standard output, standard error, exit codes, and content-addressable Git tree SHAs.
  - Ingests Blake3 cryptographic receipts generated by the Aegis sandbox for verifiable execution provenance.
- **Token-Aware Context Compaction**:
  - Compresses verbose tool output logs while preserving active task objectives and critical code diffs.
  - Maintains context consumption at a stable $O(1)$ token floor across long-running tasks.

## Quick Start

### 1. Run Unit & Integration Tests (Zero Dependencies)
```bash
python3 tests/run_tests.py
# Runs all 11 unit and integration tests
```

### 2. View Checkpoint History
```bash
python3 -m chronos.cli history --db .chronos/checkpoints.db
```

### 3. Render Terminal DAG Execution Tree
```bash
python3 -m chronos.cli visualize --db .chronos/checkpoints.db
```

### 4. Trigger Workspace Rollback
```bash
python3 -m chronos.cli rollback <snapshot_id> --workspace .
```

### 5. Run Unified Triad End-to-End Demo
```bash
python3 examples/unified_triad_demo.py
# Connects Aegis sandbox execution, Chronos rollback, and Inferno telemetry
```

## Python In-Memory COW VFS Usage

```python
from chronos.vfs import MemoryCOWWorkspace

# 1. Initialize virtual in-memory workspace
vfs = MemoryCOWWorkspace(base_disk_dir="./my-project")
vfs.write_file("src/engine.py", "def compute(): return 1")

# 2. Capture O(1) memory snapshot
snap_id = "checkpoint_1"
root_hash = vfs.snapshot(snap_id)

# 3. Fork speculative candidate branches
branch_a = vfs.fork_branch("candidate_a")
branch_b = vfs.fork_branch("candidate_b")

branch_a.write_file("src/engine.py", "def compute(): return 42")
branch_b.write_file("src/engine.py", "def compute(): raise ValueError()")

# 4. Instant rollback without touching physical disk
vfs.rollback(snap_id)

# 5. Flush winning branch to physical disk
branch_a.materialize_to_disk("./my-project")
```

## Technical Comparison

| Dimension | Flat Context Loop (Naive Agent) | Chronos DAG Orchestration |
| :--- | :--- | :--- |
| **State Representation** | Flat message array | Directed Acyclic Graph with immutable snapshots |
| **Rollback Mechanism** | None (manual undo prompt) | $O(1)$ In-Memory COW pointer swap / Git tree reset |
| **Branching Model** | Linear (single-path execution) | Multi-branch speculative parallel execution |
| **Storage Architecture** | Ephemeral process RAM | Local-first SQLite with Write-Ahead Logging (WAL) |
| **Context Growth** | $O(N)$ linear token explosion | $O(1)$ token floor via semantic compaction |
| **Execution Safety** | Vulnerable to host side effects | Verified via Aegis Blake3 cryptographic audit receipts |
